**v1 尚未實作。** 這個指令現在只會回報一件事，然後結束：

```
sdd-graph change --task <taskName>
→ stderr: {"kind":"error","code":"not_implemented","message":"/sdd-graph:change 尚未實作：v1 只預留入口，圖狀態仍由階段路由推進。"}
→ exit 1
```

它**不會**默默地把請求忽略掉 —— 靜靜地忽略一個請求，等於讓人以為它被處理了。

## 為什麼先不做

舊的 `/sdd-agent:change` 是一條單向帶：它改寫已經產出的文件，然後從頭再走一次。
現在的架構不是這樣：**圖擁有階段路由**，會話只負責把工作單做完。所以「改需求」
不是「重跑一次」，而是**讓圖改道**：

- 圖得能從 checkpoint 回到**更早**的階段（例如 spec 寫完了才發現 PRD 少了一條需求）。
- 圖得能**重新發**同一張工作單，而且要帶著「上一次為什麼被退回」的理由。
- 圖得能讓被改動的下游文件（spec、e2e 計畫、tasks）**失效**，而不是留下舊的產物。

在這三件事做出來之前，`change` 只能是個預留的入口。

## 未來要支援的方向

- `sdd-graph change --task <n> --to <stage>`：把這一輪退回某個階段重走。
- 退回時要標記受影響的下游文件，讓它們在工作單裡被重寫。
- 每一輪的產物都要能追到是第幾版生成的（否則改完之後沒人說得清哪一份是最新的）。

在那之前，想改需求請直接說要改什麼，圖會在下一個工作單裡把它當成「上一次為什麼被退回」的理由。
